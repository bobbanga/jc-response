# 提问示例

纯教学使用这里的合成样例。样例不代表真实回盘，教学时不联网 JC，也不读本地业务库。不要把真实姓名、密码、Token 或真实单据当作学习前提。

## 市场入口的三条独立问法

展示示例最多保留中英文各三条。它们不依赖用户已经完成其他示例，不能自动串行执行。

1. “我是第一次用，帮我接入JC回盘助手，并教我怎么提问。”
   先检查和接入，再给合成教学示例；不自动读取真实回盘。安装和配置写入先取得本人同意。
2. “读取一批5条回盘，整理成清单，不保存、不继续。”
   前置条件满足后使用 `list_only`、`limit=5`、`save=false`，完成本批就停止。
3. “读取一批5条回盘及详情，导出同一批的30列中文CSV，完成后停止。”
   这是一次明确的读取和导出请求。前置条件满足后使用 `api_full`、`limit=5`；未明确要求保存快照时仍使用 `save=false`。读取成功后，用工具返回的同一个 `batch_id` 调用产品导出，不再读取、不额外保存快照、不续读；临时结果失效则报告，不自动补抓。导出会写入本地 CSV，详情字段可能为空。

“导出刚才这批，不重新读取”仍是已有批次后的追问，不占用市场独立入口；当前会话没有可引用批次时先说明，不能自行采集一批替代。

## 1. 第一次认识 JC MCP

适用：用户问这是做什么的。

可以这样说：“用我自己的 JC 账号，把一小批回盘读进对话里核对。”

结果应是说明三层分工：客户端负责理解这句话，JC MCP 负责调用本机产品，产品负责账号、预算和执行。不访问 JC，不写文件。失败时只重讲这三层，不开始安装。

## 2. 把模糊需求说清楚

适用：用户说“帮我处理一下回盘”。

请用户补齐：处理对象、数量、结果形式、是否保存、停在哪里。不知道数量时只问数量，不默认 20。

示例：“读取一批 5 条回盘，整理成清单，不保存，不继续。”

不访问 JC，直到用户把这五项说清并明确要求执行。

## 3. 读取一批清单

示例：“读取一批 5 条回盘，整理成中文清单，标出缺失信息，不保存，不继续。”

结果应使用 `mode=list_only`。这是清单预览，不是完整业务表。报告来源、记录数、读取范围和缺失字段。不要说“最新 5 条”，除非产品返回了有证据的排序。这是一次 JC 读取。不写文件。数量缺失、超限或工具失败时停止，不改走开发 CLI。

## 4. 核对已有信息

示例：“只根据刚才这批，列出已知事实、缺失信息和需要人工核实的问题，不补抓。”

不访问 JC，不写文件。没有可靠来源的港口、金额、币种和联系人保持缺失。`missing_fields=[]` 不表示全部业务字段都完整。没有刚才这批时，说明没有可核对的结果，不重新读取。

## 5. 查看与导出同一批

示例：“看刚才第 2 条已有详情。” “导出刚才这批，不重新读取。”

查看和导出都不增加 JC 读取。`list_only` 导出只能得到信息不全的中文业务表，不能用来验收完整业务表。用户明确要求读取并导出业务表、且需要详情列时，下一次读取才使用 `api_full` 和用户给出的数量。导出必须使用相同 `batch_id` 和产品导出工具。不要用脚本另写 CSV。只有返回 `csv_schema=JC_response_business/1.0` 才是中文业务表。`response_flow/1.1` 不能单独证明。已安装的 v1.2.0-r1 仍是旧技术表 `JC_response/1.1`，看到它时提示升级，不改走开发 CLI。运行包只从固定的 v1.3.0-r2 地址下载。没有用户同意时不要覆盖正式安装。

合成表示例，不是真实回盘：回盘ID `R-SYN-001`，柜型柜量 `40HQ*2/20GP*0`，参考报价留空。不要把教学样例写进用户的导出文件。

## 6. 下一批与错误

示例：“沿刚才的位置，下一批再读取 5 条，完成后停。”

使用上一批返回的 `continuation_id`，不手算页码。预算不足、正在忙或结果过期时，按业务规则解释并停止。不循环重试，不换入口。下一批是一次新的 JC 读取。用户没有明确提出时，安装或教学结束都不自动读取。
