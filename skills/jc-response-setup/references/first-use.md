# 第一次配合

对新手只说明接下来会完成什么，不先讲协议和目录。

每次只请本人做一个当前必须的动作。自动检查不必逐项停下来询问，也不要一次输出整本说明。

目标顺序：

1. 分辨用户是要学习，还是要办一件已经说清的事。
2. 学习请求停在说明和合成示例。
3. 接入请求先检查已知产品位置和可见的 `jc-response`。
4. 缺安装就安装，缺配置就配置，缺登录或范围开通就只补那一项。
5. 接好后只查一次状态，不读取回盘。
6. 用合成示例教用户怎么提问。
7. 用户明确提出业务任务后，才调用正式 MCP。

本人需要参与的动作包括：同意本次安装或写配置、确认客户端里实际出现的信任提示、在 JC 页面输入密码或验证码、首次确认范围说明。没有弹窗就如实记录，不编造信任结果。

工具暂时在旧会话里不可见时，告诉用户需要新建一个会话，返回 `awaiting_client_reload`。不要改用产品 CLI 读取数据，也不要反复重启。

交接只保留阶段、版本、核验结果和下一步。交接记录不能代替下一次核验，也不证明授权还在。

## 接入后的第一句话

安装核验只调用状态工具；成功后给一个适合当前状态的示例，由用户决定是否开始真实任务，不自动读取。不要把“接入并教我使用”解释为允许采集数据。

已有可用安装就复用，不把新手教学变成重复下载安装。解释预算、权限或字段缺失时优先说业务含义，工具名和原始 JSON 按需展开。

登录过程中状态未变化时，不逐次播报“继续等待”。继续按工具要求在同一个任务、既有超时内有界查询；只在开始、需要本人操作、成功、取消、失败或超时时提示。不得重复启动连接或无限轮询。
