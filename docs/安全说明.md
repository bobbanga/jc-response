# JC Response 安全说明

JC Response 只做有边界的回盘读取、本批查看、本地保存和 CSV 导出。用户主动连接时，才打开登录窗口。

- 用户使用自己的 JC 账号。发行包不携带登录态、Cookie、密码或 `.env`。
- 程序不保存密码，只保存完成登录后业务所需的 JCB 登录态。
- 登录态使用 Windows DPAPI 的当前用户范围保护。这不能防止同一 Windows 用户权限下的恶意程序读取它。
- 发行版不读取开发目录、旧环境变量或其他产品里的登录态。
- 退出登录只删除本产品的本地登录态，不删除回盘数据，也不声称远端会话已经撤销。开通状态随退出撤销，滚动预算计数保留。
- 不同 JC 账号的数据放在不同的本地账号目录，不会静默混用。
- SQLite、raw JSONL、checkpoint 和 CSV 都在当前用户的产品目录。
- 单次读取是 1–20 条、1 页。滚动 24 小时预算是 10 次新读取、100 个记录额度和 400 次上游 HTTP 尝试。MCP 参数、Skill 文字和环境变量都不能提高这些上限。
- 首次范围确认由用户本人完成。一次普通对话或工具调用不能代替这句确认。确认后的范围内读取不再逐批打开许可窗口。
- MCP 不提供开通、提额、清零、任意命令、任意 URL 或任意数据库工具。
- 不采集 DOM 明文联系人。登录窗口也不提取页面联系人。
- 不最终报价，不自动提交报价，不自动处理危险品，不发送消息。
- JC 凭证只由本地程序持有，不放进 MCP 配置、Skill 或模型上下文。
- 读取结果中的字段会提供给当前 AI 客户端。是否由云端模型处理取决于该客户端的配置。
- `missing_fields=[]` 只表示当前检查范围内的字段未缺失。来源不足的其他字段保持为空。
- CSV 是固定 30 列。当前版本不做旧表兼容。

发行包由 Nuitka standalone 生成，目录里不放项目明文 Python 源码。这不等于客户端代码绝对不可逆向。登录所需的第三方运行文件可以留在发行包里。

WorkBuddy 配置只把 `jc-response` 指向已安装的 `jctrans-mcp.exe`。写入前保留其他服务器。信任由用户本人确认。程序不修改信任记录。

## r1 发布与升级边界

当前未签名。SHA256 只对照文件内容，不代替发布者身份认证或恶意软件检查；不要关闭系统安全防护。

r1 没有重编译或修改 bin/。静态扫描未发现实际用户凭据或业务数据文件；二进制保留旧 Ehelp 路径拒绝检查常量，不宣传“完全没有开发路径字串”。

certifi/cacert.pem 是 CA 公钥证书集合，非私钥。Playwright、Tcl/Tk、JSON Schema、DLL/PYD 及许可证属于第三方运行内容。Playwright 自带 Skill 不是本产品日常 Skill。

升级不得删除、替换、迁移或回滚凭证、授权、预算和业务数据；不为验证升级主动退出登录。旧逐批许可不自动等于新范围开通。资料更新与安装器实际行为详见升级说明，Windows 动态验证尚待完成。

同权限本机程序仍可能操作用户文件；预算只覆盖当前产品数据根，不覆盖其他 Windows 用户或电脑，不能宣传为不可绕过的全局额度。JC Response 不是 JC 官方产品。
