## 2. 静态复核

核对 ZIP 外部哈希、路径安全、CRC、内部全部校验和，以及三个产品 EXE 的哈希。与原审阅包对照，bin/ 必须逐字节不变。原包没有时只报告当前哈希检查，不能伪称做过双包比较。

源码所描述的安装分支与本包二进制未建立可复现构建对应关系，必须补下一节的实际 EXE 测试，不能只读私有源码就写 PASS。

## 3. 隔离 Windows 测试

使用本包编译 EXE，不用 Python 源码入口替代。先核对当前实现支持的隔离目录方式，再仅在测试子进程中设置临时 USERPROFILE、LOCALAPPDATA、APPDATA 和产品路径配置；不得修改永久环境变量。隔离机制不明时 BLOCKED，不能冒险访问真实凭证或配置。

测试使用无秘密哨兵文件，不登录 JC、不发读取请求、不运行 authorize/logout/reset。

| 场景 | 要记录的证据 |
|---|---|
| 新安装 | --install-user 的退出码、JSON status、全部安装文件哈希 |
| 重复安装 | 相同包重复安装，实际返回与文件变化 |
| 同程序、不同说明 | 临时源副本只改说明不改 EXE，是否 already_installed 且已安装说明未更新；该副本不能当发行包 |
| 资料刷新 | 用正确修订包按升级白名单更新，再核对全部文件 |
| 旧版升级 | 有真实旧包时测试；只有模拟旧文件时必须标“模拟”，不能称旧程序动态验收 |
| 配置 | 临时配置保留其他服务器及顶层字段；损坏 JSON、同名冲突停止 |
| 数据保留 | 数据/预算哨兵文件在安装与资料刷新后未被删除、替换或重置 |
| 状态 | stdio 初始化、工具列表和一次 jctrans_status；契约正确，未登录是预期，不读取业务 |

同时检查失败是否可能部分复制；退出码 0 和 changed=false 都不能代替文件核对。测试不修改机器系统时间，不停安全软件。

发现必须改安装器、DLL 或业务内核才能解决的缺陷时，停止实际升级并报告。不手工拼装二进制，不暗中改预期哈希。

## 4. 本人电脑的升级授权与边界
