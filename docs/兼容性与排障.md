# 兼容性、依赖与已知限制

本页对应已审核的 Windows 包 1.2.0-r1，不把未来架构愿景写成已支持功能。

| 环境或功能 | 当前状态 |
|---|---|
| Windows x64 | 当前唯一发行平台；维护者报告已做安装/资料升级和 stdio 状态测试 |
| WorkBuddy Windows 桌面端，自定义本地 MCP | 维护者报告新会话 status 已返回 response_flow/1.1、预授权 active、凭证 present |
| WorkBuddy 市场安装 | 尚未完成适配/审核，不等于上述自定义连接测试 |
| macOS / Linux / Windows ARM 原生 | 无对应发行包；不要把 x64 ZIP 宣称全平台支持 |
| Codex / Claude Code 等本地 MCP 客户端 | 架构目标可适配；此包本轮未给出完整真实业务验收，不宣称即装即用 |
| 仅网页/远程云端 AI | 本地 stdio 不是可填 URL 的远程 MCP；云端不能直接启动你电脑的 EXE |
| 无管理员权限 | 按当前用户目录安装；具体企业设备策略可能仍限制执行 |
| 代码签名 | 未签名；不要求关闭系统防护、设置全局执行策略或使用绕过开关 |
| 业务账号 | 用户本人 JC 账号和其已有权限；本工具不授予网站额外权限 |

## 依赖与隐私

本机 Edge 用于用户主动登录；发行包含 Playwright 驱动，但不保证企业策略、代理或账号风控下都能登录。JC 与 AI 客户端需要的网络由用户环境决定。普通使用不需要系统 Python、Node.js、Nuitka 或私有源代码。

JC 登录态由本机产品管理。发给 AI 客户端的回盘字段可能由云模型处理；请先确认自己的业务数据能否交给所选客户端。公开仓免费分发不表示 JC 服务、AI 套餐或未来附加服务全部免费；费用以各提供方为准。

## 常见问题

| 现象 | 处理 |
|---|---|
| Releases 没有 Windows ZIP | 资产尚未发布或当前不可用；不要把 Source code ZIP 当替代安装包 |
| 版本也是 1.2.0，为何还要升级 | 历史候选重复使用版本号，比较 ZIP/EXE 哈希与契约，不只看名字 |
| already_installed 后说明还是旧的 | 已实测同二进制会跳过复制资料；按升级说明精确刷新，不清理数据 |
| target_in_use | 正常停止目标 JC 进程/连接后重试；失败可能部分复制，先核对，不能一律当作原文件未变 |
| conflict / 坏 JSON / 同名非本产品 | 安装器应停止；备份后检查目标差异，不覆盖整份配置，不删除其他服务绕过 |
| MCP 红灯或旧路径 | 确认 command 是当前用户正式安装目录内的 jctrans-mcp.exe，不是 ZIP、dist、临时目录或全局 CLI |
| 无新 Trust 弹窗 | 如实记录。以前的状态可能被复用；不修改信任记录来造出“已确认” |
| status 正常但 AI 要调用开发命令 | 先处理旧 Skill 冲突并新建会话；status 成功不能证明 Skill 已加载 |
| setup_required / authorization_revoked | 本人阅读范围说明并开通；MCP 不提供代开通命令 |
| auth_required / auth_expired | 本人通过产品重新连接；不要刷新开发 CLI 的另一套 Token |
| budget_exceeded / busy | 停止；不换客户端、重登、清库或等待循环来绕过 |
| result_expired | 临时批次已不可用；不自动重新采集，先由用户决定 |
| list_only 没有完整详情 | 如实缺失；后续新读取需明确 api_full，不能伪装本批已补全 |
| CSV 有空列 | 固定 30 列不等于每列有值；只保留可靠来源，不猜报价、港口或联系人 |
| 文件路径不能点击下载 | 导出在运行 MCP 的 Windows 电脑中，使用本机文件入口，不是公共附件 |

## 升级与市场连接共存

当前自定义 jc-response 与未来市场安装项可能重复注册。市场适配前不保证同名自动合并。只能在明确识别和本人确认后迁移目标项；scys-mcp 和其他服务始终保留。不在启动器中自动创建第二份用户配置。

## 验收范围

后续 Windows 报告见[验收补充](../releases/1.2.0-r1/WINDOWS_VALIDATION.md)。该报告证明的安装/状态项目不等于新用户完整读取与导出已验收，也不等于 WorkBuddy 市场审核通过。额度控制属于当前用户产品数据根，不是跨电脑全局配额；同权限本机程序仍可访问其他开发工具。

报告问题请去 [Issues](https://github.com/bobbanga/jc-response/issues)，带程序/契约/客户端版本、包哈希、失败阶段和脱敏错误。不要上传真实凭据、完整 mcp.json、浏览器 Profile、业务 CSV 或数据库。
