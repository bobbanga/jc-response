# Windows 快速开始

适合会下载、解压文件并能打开 PowerShell 的用户。只需 Windows x64、Edge、可正常对话的 WorkBuddy 桌面端和自己的 JC 账号。不需 Python、Node.js、Git 或开发仓库。当前包未签名；不要关闭安全软件或绕过企业策略来运行。

## 1. 选对文件

从本仓 [Releases](https://github.com/bobbanga/jc-response/releases) 取得 `JC_response-windows-x64-1.2.0-r1.zip`。Source code ZIP 不是安装包。没有这个资产说明尚未上传；当前已持有维护者提供的同哈希包，也可用同样流程验收。

用 PowerShell 检查文件，把第一行改为实际下载位置：

```powershell
$Zip = 'C:\Downloads\JC_response-windows-x64-1.2.0-r1.zip'
if ((Get-Item -LiteralPath $Zip).Length -ne 122270089) { throw '文件大小不符，停止' }
$Expected = '91b6df6dd4ae0ee4684c8d4946956ca2599294e118014837f3a339bb717be713'
if ((Get-FileHash -LiteralPath $Zip -Algorithm SHA256).Hash.ToLowerInvariant() -ne $Expected) { throw 'SHA256 不符，停止' }
'文件身份匹配；这不是代码签名或安全软件认证。'
```

`C:\Downloads` 是示例，不是固定目录。核对后用资源管理器“全部解压”到一个新文件夹，找到包含 bin/、docs/、skills/ 的根目录，不要直接在 ZIP 内运行。

## 2. 安装或升级

已有旧安装的用户先读[升级说明](升级说明.md)。保存任务并正常停用旧 JC 连接/退出占用它的客户端，不强杀进程，不删除数据目录。程序目录、数据目录分别为：

```text
%LOCALAPPDATA%\Programs\JC_response
%LOCALAPPDATA%\JC_response
```

自动协助方式：把[接入提示词](接入提示词.md)和实际解压路径交给 Cursor 或 WorkBuddy。本机已有正在运行的 JC 连接时，优先由 Cursor 协助升级，避免让 WorkBuddy 结束自己。

具备基础的用户也可在阅读完整[安装说明](安装说明.md)后执行这两条产品命令。把 `$Package` 改为自己的解压根目录：

```powershell
$Package = 'C:\Downloads\JC_response-r1'
& (Join-Path $Package 'bin\JC_response.exe') --install-user --json
# 先人工核对上一条退出码与 JSON status，再单独执行下面一条：
& "$env:LOCALAPPDATA\Programs\JC_response\bin\JC_response.exe" --configure-workbuddy --json
```

第一条仅接受 installed/upgraded/already_installed，第二条仅接受 configured/already_configured。即使退出码为 0，JSON 报 conflict、target_in_use、target_has_data 或 install_required 也必须停止。不要一次盲跑全部命令。

特别注意：already_installed 不证明新说明和 Skill 已复制。已有安装需核对完整运行文件和资料；有差异时按升级白名单处理，不手工拼装 EXE/DLL。升级保留原凭证、授权、预算和业务数据，不以重装清零。

## 3. 本人连接账号与开通范围

配置只管理 jc-response，不修改 scys-mcp 或其他连接。打开 WorkBuddy，完成实际出现的 Trust/启用步骤并新建会话。没有弹窗不需要伪造一次信任，也不据此断言所有版本都不再确认。

需要登录或首次开通时，从开始菜单打开 JC Response。本人在 JC 页面完成密码、验证码；本人在产品窗口阅读并确认有界权限。旧有效凭证不等于已经开通，已有有效授权无需为升级重复开通。首次设置可以使用窗口，完成后日常读取不需要保持主窗口打开。

## 4. 核对 Skill，别让 AI 调错程序

安装目录含 `skills/jc-response-preview/SKILL.md`，但复制产品文件不等于客户端已加载它。使用当前 WorkBuddy 提供的技能导入方式，确认名称为 jc-response-preview、版本 1.2.0、正文修订 r1、契约 response_flow/1.1；找不到入口时让安装助手核对当前客户端文档，不猜路径。

以前装过 `jctrans-response-assistant`，或看到 Skill 要求 `inquiry-response assistant`、开发目录、全局 jctrans 时，不要执行。先保留备份并经本人确认停用该冲突项，备份移出技能扫描根，再开新会话。不要删除其他技能或整个开发环境。

## 5. 只查状态，再开始业务

新会话先发：

```text
只调用一次 jc-response 的 jctrans_status，不读取、保存或导出回盘。
报告契约版本、预授权状态、授权模式、凭证状态，不显示凭证或完整配置。
```

目标契约为 response_flow/1.1。正常已开通时，状态应表达 active / scoped_preauthorization。凭证 present 只是产品状态，不是一次新的远端在线验证；未登录/未开通按真实状态处理，不以其他账号兜底。

你决定开始读取后，再说：

```text
使用 JC Response 读取一批 5 条回盘，list_only，不保存，不继续。
```

需要完整字段时在本次读取前说明使用 api_full；list_only 批次的详情工具不补抓。导出说“导出刚才这批，不重新读取”；文件是本机路径，不是公共下载链接。

失败时给出准确错误，不让 AI 搜索全局 jctrans、刷新开发 Token、自动连续重试。更多情况看[兼容性与排障](兼容性与排障.md)。
