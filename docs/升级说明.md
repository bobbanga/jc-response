# 已有 JC Response：升级与回退

本说明对应 1.2.0-r1 文档修订候选。程序版本仍为 1.2.0，不能只比较版本字符串。

## 三种情况

| 现状 | 处理 |
|---|---|
| 尚未安装 | 运行已验证包的 --install-user，核对全部文件再配置 |
| 旧运行文件不同，即使也叫 1.2.0 | 先正常停止旧进程、备份，再执行安装器并逐文件核对 |
| 全部 bin/ 文件相同，仅说明/Skill 不同 | 安装器可能提前返回 already_installed；维护者按下述白名单刷新资料 |

源码审阅显示，提前返回条件仅核对入口存在、版本和 MCP EXE 哈希，并非所有文件。本包 EXE 对应控制流尚待 Windows 动态验收，不能用源码分析替代。

## 升级前

固定程序根为 `%LOCALAPPDATA%\Programs\JC_response`，数据根为 `%LOCALAPPDATA%\JC_response`。保留真实数据原位，不清库、不更换数据根重置预算、不为测试主动 logout。账号身份或范围变化仍按产品原规则处理，不伪造授权。

先核对 ZIP 外部哈希、内部校验和、旧程序版本及运行文件。旧版本更高、来源未知、目录含重解析点或程序目录混有用户数据时停止，不自动降级或删除。

请用户保存任务并正常停止占用目标 EXE 的进程。不要强杀其他客户端，尤其不能让 WorkBuddy 安装会话杀死自身；必要时由 Cursor 在 WorkBuddy 退出后继续。

在 Git 之外的本机私有目录备份旧程序和 MCP 配置，不输出或上传备份内容。安装覆盖可能部分完成，失败即停，不能假定 changed=false 代表未改动。

## 维护者专用：仅资料更新

本步骤需要用户授权的维护任务；不是安装 Agent 两命令白名单的扩展，也不是新增的产品命令。

1. 先证明已安装的全部 bin/ 文件与正确候选包相同，无额外未知运行文件。运行文件不符即停止，不能手工拼装混合版本。
2. 备份将替换的公开资料。发现用户自行修改过的资料，先报告，不无条件覆盖。排除目标及父路径的链接/重解析点。
3. 只复制这九个目标：docs/安装说明.md、docs/使用说明.md、docs/安全说明.md、docs/接入提示词.md、docs/升级说明.md、skills/jc-response-preview/SKILL.md、VERSION、RELEASE-METADATA.json、SHA256SUMS.txt。禁止整目录镜像、额外删除或替换 EXE。
4. 同目录临时文件后原子替换每个文件；不能宣称整套操作是事务。SHA256SUMS.txt 最后替换，且只有全部目标文件都与清单相符才完成。中途失败停止并核对/恢复这组资料。
5. 客户端独立加载的 Skill 另外核对；不猜安装目录、不擅自删除其他 Skill，不能把产品目录更新当成客户端已加载。

资料完成后再用正式安装副本执行 --configure-workbuddy。conflict 时停止，不删除已有 jc-response 来避开检查。保留其他 MCP、未知字段和信任记录。

## 回退与验收

程序未写入新数据时，可在停止进程后恢复程序/资料备份并验证哈希。新程序已迁移数据时，不假定旧程序兼容；停止交维护者判断。不得用旧数据或预算备份回滚用量。MCP 只回退本次目标项，不拿旧整份配置覆盖期间新增的其他设置。

发布前必须在隔离 Windows 环境对本包 EXE 验证：首次安装、重复安装、同程序不同说明、白名单刷新、旧版升级、占用/冲突、哨兵数据和预算保持，以及 status 实际契约。没有做的写 NOT_RUN。仅状态成功不等于真实 JC 业务验收。
