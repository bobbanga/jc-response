# JC Response 安装说明

程序 1.2.0；契约 response_flow/1.1；CSV 契约 JC_response/1.1、30 列；包修订 r1。Windows x64，未签名，当前候选尚待 Windows 升级验收。

## 文件身份

r1 不修改或重编译 bin/ 下任何文件。VERSION 保持 1.2.0，以 RELEASE-METADATA.json 的 package_revision 和外部 ZIP SHA256 区分同名历史包。SHA256 不等于代码签名。

先核对发行方另行提供的 ZIP 哈希，再解压到新目录。内部 SHA256SUMS.txt 用于逐文件完整性核对，不能单独证明来源可信。目录应含 bin/、docs/、skills/、VERSION、RELEASE-METADATA.json 和 SHA256SUMS.txt。

## 安装与接入

将接入提示词与解压目录交给 Windows WorkBuddy。已有旧安装时优先由 Cursor 按升级说明处理，避免 WorkBuddy 升级正在占用的自身 MCP。

只执行两条产品命令：

```text
<已验证解压目录>\bin\JC_response.exe --install-user --json
%LOCALAPPDATA%\Programs\JC_response\bin\JC_response.exe --configure-workbuddy --json
```

不需要用户安装 Python，不通过 PATH 找同名程序。实际成功必须同时核对退出码与 JSON status。安装只接受 installed/upgraded/already_installed；配置只接受 configured/already_configured。conflict、install_required、target_in_use、target_has_data 或其他状态停止，不删除文件或配置来绕过。

程序目录为 `%LOCALAPPDATA%\Programs\JC_response`；数据目录为 `%LOCALAPPDATA%\JC_response`。不覆盖凭证、授权、预算和业务数据，不卸载清库，不先退出 JC 登录来测试升级。

当前源码在目标入口存在、版本相同且 MCP EXE 哈希一致时提前返回 already_installed。这不是全体运行文件相等的证明，也不会继续复制说明。该分支行为仍需绑定本包 EXE 哈希做 Windows 实测。无论返回哪种成功状态，都核对全部 bin/、说明与 Skill；仅资料不同则按升级说明处理。

安装器逐文件复制不等于原子升级。先停旧进程、备份旧程序，失败时检查部分复制，不根据 changed=false 假定原安装未变。

配置只更新 jc-response，保留 scys-mcp 等其他项，不写 Token，不修改 Trust。命令必须指向正式安装目录；ZIP 路径和下载地址不是 MCP url。本人确认信任后新建会话，不能把写入配置当作客户端已启用。

安装核对只调用一次 jctrans_status，确认实际 capabilities.contract_version=response_flow/1.1。不执行业务读取、保存、导出或 status --verify。包内 Skill 文件存在不代表客户端已加载；还要核对真实加载版本，冲突时停止业务操作。

## 登录与范围

登录使用本机已安装 Edge 的独立临时窗口。密码、验证码和二次验证只由本人在 JC 页面填写。首次范围说明也由本人在产品窗口确认；安装 Agent 不代开通。已有有效 Token 不自动等于已经接受新范围。

范围开通后，明确数量的读取不逐批索要窗口许可。单次 1–20 条、1 页；滚动 24 小时 10 个新读取、100 记录额度、400 次 HTTP 尝试；最多一个活跃上游读取。这些是产品内测限制，不是 JC 官方额度。

## 发行范围

工具白名单见随包 Skill。契约或工具集合不匹配时停止，不以旧版“恰好两个工具”为准。不提供报价提交、飞书写入、调度、推送、DOM 联系人、MCP 开通/提额/清零。

静态审阅未发现产品 Python 明文源码或用户数据文件。二进制保留旧 Ehelp 路径的拒绝检查常量，因此不声称“没有任何开发路径字串”。必要 certifi CA 证书、Playwright、Tcl/Tk、JSON Schema 和运行库允许保留。没有源码文件不等于程序不可逆向。
